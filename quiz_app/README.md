# クイズ道場

スマートフォン向けのクイズアプリです。サーバーを持たない静的サイト（PWA）として動きます。
問題は `data/` フォルダの JSON ファイルで管理していて、ファイルを書き換えて公開し直すだけで問題を追加・更新できます。
アプリ本体を作り直す必要はありません。

## 特徴

- **8つの出題形式**: ○× / 四択 / 連想 / 並べ替え / 文字パネル / 多答 / 順番当て / タイピング
- **早く答えるほど高得点**: 正解で50点、残り時間に応じて最大+50点（1問100点満点）
- **新しい問題から出題**: まだ解いていない問題を優先して出すので、問題を追加すると次のプレイから出てくる
- **復習**: 間違えた問題だけを集めて出題する。正解すると復習リストから外れる
- **成績は端末に保存**: 成績や自己ベストはブラウザ（localStorage）に保存するので、サーバーやログインは不要
- **ホーム画面に追加できる**: アプリのように全画面で使え、一度開けばオフラインでも遊べる

## 手元で動かす

ブラウザの制限で、`index.html` をファイルとして直接開くと問題を読み込めません。簡単なサーバーを立てて開きます。

```sh
cd quiz_app
python3 -m http.server 8080    # Node.js があれば npm start でもよい
```

ブラウザで http://localhost:8080 を開きます。

## 問題を追加・更新する

1. `data/questions/` の中の、ジャンルごとの JSON ファイルを開く
2. `"questions"` の配列に問題を追加する（書き方は下の表と例を参照）
3. `node tools/validate.js` でチェックする（Node.js 20 以上）
4. 公開先に反映する（GitHub と公開サービスをつないでおけば、push するだけで反映される → [公開する](#公開する)）

公開したあとは、アプリを開き直すだけで新しい問題が出ます（アプリは起動のたびに問題ファイルの更新を確認します）。

注意点:

- `id` は他の問題と重ならない文字列にしてください。成績は `id` ごとに記録されるので、公開後に `id` を変えると「新しい問題」として扱われます。
- 書き方を間違えた問題があっても、その問題だけを除いて残りの問題で遊べます。除いた問題はホーム画面の下に一覧で表示されます。
- `data/manifest.json` の `updated` を書き換えると、ホーム画面に「問題データ ◯◯ 更新」と表示されます。
- 問題は自分で作ったものにしてください。市販のゲームやテレビ番組の問題をそのまま使うと、著作権の問題になります。

### 形式ごとの書き方

すべての形式で共通の項目:

| 項目 | 内容 |
|---|---|
| `id` | 問題の識別子（必須・重複不可）。例: `"rikei-009"` |
| `type` | 出題形式（必須）。下の表の英字 |
| `q` | 問題文（連想以外は必須） |
| `explain` | 解説（省略可）。答えのあとに表示される |
| `time` | 制限時間の秒数（省略可）。省略すると形式ごとの標準時間 |
| `genre` | ジャンル（省略可）。省略するとファイルの `"genre"` になる |

| `type` | 形式 | 必要な項目 | 標準時間 |
|---|---|---|---|
| `ox` | ○× | `answer`: 正しければ `true`、誤りなら `false` | 10秒 |
| `choice` | 四択 | `answer`: 正解、`wrong`: 誤答1〜5個（多いときは毎回3つ選ぶ） | 15秒 |
| `rensou` | 連想 | `hints`: ヒント2〜6個（開く順）、`answer`、`wrong` | 20秒 |
| `sort` | 並べ替え | `answer`: 1文字ずつに分けて出題。単語ごとに分けたいときは `pieces` | 20秒 |
| `panel` | 文字パネル | `answer`: ひらがなかカタカナ。漢字などのときは `dummies`（ダミー文字） | 20秒 |
| `multi` | 多答 | `correct`: 正解（1つ以上）、`wrong`: 誤答（合計8個まで） | 20秒 |
| `order` | 順番当て | `items`: 正しい順番で2〜6個 | 20秒 |
| `typing` | タイピング | `answer`、`alt`: 別解（省略可）。ひらがな/カタカナ・全角/半角の違いは自動で正解扱い | 25秒 |

例:

```json
{ "id": "rikei-009", "type": "ox", "q": "水は4℃のときに最も密度が大きい。", "answer": true }

{ "id": "rikei-010", "type": "choice", "q": "地球に一番近い恒星は？",
  "answer": "太陽", "wrong": ["シリウス", "ベガ", "プロキシマ・ケンタウリ"] }

{ "id": "rikei-011", "type": "rensou", "hints": ["H2O", "100℃で沸騰", "0℃で凍る"],
  "answer": "水", "wrong": ["塩", "鉄", "酸素"] }

{ "id": "rikei-012", "type": "sort", "q": "細胞の遺伝情報を担う物質は？", "answer": "デオキシリボ核酸",
  "pieces": ["デオキシ", "リボ", "核酸"] }

{ "id": "rikei-013", "type": "panel", "q": "雨上がりの空にかかる、七色の光の帯は？", "answer": "にじ" }

{ "id": "rikei-014", "type": "multi", "q": "次のうち、気体の元素をすべて選べ。",
  "correct": ["水素", "酸素"], "wrong": ["鉄", "金"] }

{ "id": "rikei-015", "type": "order", "q": "小さい順に選べ。", "items": ["原子", "分子", "細胞"] }

{ "id": "rikei-016", "type": "typing", "q": "H2O の物質名は？", "answer": "水", "alt": ["みず"] }
```

### ジャンルを増やす

1. `data/questions/` に新しいファイルを作る（例: `food.json`。中身は `{ "genre": "food", "questions": [ ... ] }`）
2. `data/manifest.json` の `genres` に `{ "id": "food", "name": "グルメ", "hue": 15 }` を追加する
   （`hue` はジャンルの色。0〜360 の色相で、0=赤、120=緑、240=青）
3. 同じく `packs` に `"questions/food.json"` を追加する

## 公開する

`quiz_app` フォルダの中身をそのまま置けば、どこでも動きます（ビルドは不要）。
次のような無料の静的サイト公開サービスを GitHub のリポジトリとつなぐと、GitHub に push するたびに自動で公開し直されます。
問題を追加するときは、JSON を編集して push するだけになります。

- **Cloudflare Pages** / **Netlify**: リポジトリを選び、ビルドコマンドは空のまま、公開するフォルダに `quiz_app` を指定する。プライベートリポジトリでも無料で使える
- **GitHub Pages**: 無料プランでは公開リポジトリが必要。アプリがサブフォルダにあるので、公開用の GitHub Actions を追加して使う

オフライン対応（Service Worker）は HTTPS で公開したときに有効になります。上のサービスはどれも HTTPS です。

## ファイル構成

```
quiz_app/
├── index.html            画面の入れ物
├── css/style.css         デザイン（ライト: 方眼ノート / ダーク: 黒板）
├── js/
│   ├── main.js           画面の流れ（ホーム → 出題設定 → クイズ → 結果）
│   ├── formats.js        出題形式ごとの画面
│   ├── logic.js          判定・得点・出題の選び方（画面に依存しない）
│   ├── schema.js         問題データのチェック（アプリと validate.js で共通）
│   ├── normalize.js      タイピングの表記ゆれ吸収
│   ├── data.js           問題データの読み込み
│   ├── storage.js        成績と設定の保存
│   ├── sound.js          効果音（Web Audio で合成。音声ファイル不要）
│   ├── dom.js, util.js   小さな共通処理
├── data/
│   ├── manifest.json     ジャンルと問題ファイルの一覧
│   └── questions/*.json  問題（ジャンルごと）
├── sw.js                 オフライン対応
├── manifest.webmanifest  ホーム画面に追加したときの名前やアイコン
├── tools/validate.js     問題データのチェック
└── tests/                テスト（node --test）
```

## テスト

```sh
cd quiz_app
node --test               # 判定・得点・出題・問題データのテスト
node tools/validate.js    # 問題データのチェックとジャンル×形式の問題数の表
```

GitHub に push すると、GitHub Actions（`.github/workflows/quiz-app.yml`）で同じチェックが自動で実行されます。

## これから追加できること

- CPU 対戦（トーナメント風に勝ち上がる）
- アプリ内の問題作成フォーム（JSON を手で書かずに済む）
- 線結び・画像クイズなどの形式
- 友達とのリアルタイム対戦（ここからはサーバーが必要）
